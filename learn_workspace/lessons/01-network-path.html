The network path: what happens when you click "Send next"

On the Outreach page you click Send next. Eventually an email leaves your Gmail account. Between those two moments, a request crosses six layers. If you can narrate each one and say how it fails, you can answer the classic interview question "what happens when you type a URL and press Enter" with real depth.

1. The request leaves the browser

The page calls fetch('/api/outreach/send-next', {method:'POST'}) (see frontend/src/services/api.ts). The path is relative, so the browser sends it to the page's own origin: http://localhost:3000 in development.

An origin is scheme + host + port. The browser's same-origin policy lets a page read responses only from its own origin. That is why origins matter for everything below.

2. DNS: names to addresses

The browser needs an IP address for localhost. It checks its cache, then the OS (/etc/hosts maps localhost to 127.0.0.1 and ::1), and for real sites asks a recursive resolver, which walks root, .com and the site's authoritative servers. Answers carry a TTL so they can be cached.

  • Failure mode: stale cache after a server move; a resolver that is down looks like "site down".
  • Where it shows up here: tiga/config.py defaults HOST to 127.0.0.1, not 0.0.0.0, so only your machine can reach the API.

3. TCP: a reliable connection

TCP builds a connection with a three-way handshake: SYN, SYN-ACK, ACK. It then numbers bytes, retransmits losses, and slows down when the network is congested. The cost is one round trip before any data flows, which is why browsers reuse connections (keep-alive) and why HTTP/3 moved to QUIC over UDP.

  • A port picks the program on the host: 3000 (Vite), 8000 (FastAPI).
  • Failure modes: connection refused (nothing listening, your API is not running), timeouts (packets dropped), resets.

4. TLS: privacy and identity (in production)

Locally we use plain HTTP. On a real host, TLS runs after TCP: the server presents a certificate proving it owns the name, both sides agree on keys, and everything after is encrypted and tamper-evident. It is why a logged-in session cookie can safely cross a coffee-shop network.

  • Failure modes: expired certificate, name mismatch, clock skew.

5. HTTP: the conversation

POST /api/outreach/send-next HTTP/1.1
Host: localhost:3000
Origin: http://localhost:3000
Content-Type: application/json

A method (POST means "do something"), a path, headers, an optional body; the response has a status code (200, 403, 422, 500), headers and a body. Idempotent methods (GET, PUT, DELETE) can be safely retried; POST cannot, which is exactly why Tiga's daily report uses a database claim to stay at-most-once (lesson 2).

6. The Vite proxy, then FastAPI

Port 3000 is the Vite dev server. It serves the React app and proxies /api/* to 127.0.0.1:8000 (see frontend/vite.config.ts). A reverse proxy is the same idea you will meet in production as nginx, a load balancer or a CDN: one public entrance, many private services behind it.

FastAPI (running on uvicorn, an ASGI server) matches the path to send_next in tiga/outreach_api.py. Before that, a middleware in main.py checks the Origin header on every state-changing request.

7. CORS and CSRF: two different problems

  • CORS relaxes the same-origin policy: the server tells the browser which other origins may read its responses. It protects reads.
  • CSRF is a malicious page making your browser send a state-changing request to a site where you are logged in. CORS does not stop the request from being sent. Tiga's refuse_cross_site_writes rejects any write whose Origin is not local or explicitly allowed (ALLOWED_ORIGINS).
Interview trap: "we have CORS so we're safe from CSRF" is wrong. Say why.

8. Out to Gmail

The handler runs mailer.send_next in a worker thread (asyncio.to_thread) because the Google client library blocks. That thread makes its own outbound HTTPS call to gmail.googleapis.com: DNS, TCP, TLS, HTTP again, authenticated with an OAuth access token. Gmail then delivers by SMTP between mail servers, where SPF, DKIM and DMARC decide whether the receiver trusts it (lesson 9).
